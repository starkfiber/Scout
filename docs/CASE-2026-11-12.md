# Scout V2 gap review — 12 November 2026

Target: the local Scout preview, public GitHub README, and `starkfiber.my/scout` landing page. Success means the public presentation shows actual product evidence, explains browser/local capabilities accurately, and the working explorer gains a real interactive visual layer.

## Observed

- The local explorer lists, sorts and searches path metadata; it cannot move, rename, preview contents or replace Finder. Evidence: `scout/core.py`, `scout/server.py`, `assets/app.js`, `tests/test_core.py`.
- The public site is live. It has an interactive **design preview** and links to GitHub, but no Mac download. Its example storage map is illustrative, not connected to the visitor's files. Evidence: live page inspection at `https://starkfiber.my/scout`.
- The public README previously lacked a screenshot. The repository now includes a screenshot from a safe Scout demonstration folder, an explicit capability table and a browser/privacy boundary. Evidence: `README.md`, `docs/images/scout-preview.png`.
- The initial single Blender render was static. The current local build has separately rendered board/data layers and an accessible separation toggle. Evidence: `assets/build_ssd.py`, `assets/index.html`, `assets/style.css`, `assets/app.js`; browser toggle checked.
- RF² 0.11 bounded MCP/Core reports no filesystem access. Its trusted systems compiler now builds Scout's one-directory, NUL-separated native listing helper. Scout invokes that helper for folder names when installed; Python still handles metadata, indexing, filtering and fallback. Four tests pass, including matching RF²/Python results for Unicode and newline filenames. Evidence: installed `rf2 status`, `rf2/build.sh`, `tests/test_core.py`, `docs/RF2.md`.

## Remaining acceptance gaps

1. A signed, installable Mac app with a documented permission flow and real release artifact.
2. Complete RF² recursive enumeration and metadata pipeline, benchmarked against the same Python workload; the current one-directory hybrid was slower in its 500-entry fixture.
3. Filesystem change tracking, incremental index freshness, large-folder virtualization and long-running CPU/memory measurements.
4. Recoverable organizer actions and a clear undo/verification journal before any mutation feature.
5. A browser-only folder picker could be built as a separately consented, limited mode. It cannot silently enumerate a whole Mac or provide privileged drive metrics.
6. The 3D scene is a two-layer illustration. Component-level selection, zoom, temporal comparison, process-attributed I/O and SSD temperature/health need supported telemetry and separate validation.

No personal file inventory, private screenshots, or credentials were sent to the public site or engineering memory.
